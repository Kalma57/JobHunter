**4. לכל משרה בתכנית:**
- **התאמה `exact` למשרה בלוח** ← **לא יוצרים משרה חדשה.** מעדכנים את המשרה הקיימת: מוסיפים ל-`sightings` (רשימה) את `{source, url, date: D}`. `update` מחליף רשימה שלמה — לשלוח את הרשימה הקיימת מתמונת המצב **ועוד** הפריט החדש. אם המשרה הנכנסת מאתר החברה והקיימת מאתר חיפוש — `url` ו-`apply_url` של אתר החברה מחליפים (אתר החברה הוא המקור). **הסטטוס לא משתנה** — משרה שסומנה הוגש / בהמתנה / לא מעוניין נשארת כך ולא חוזרת כחדשה.
- **התאמה `exact` ל-`inbox:...`** (אותה משרה הגיעה פעמיים הבוקר) ← מטפלים רק בראשונה, ומוסיפים את השנייה כ-`sightings` שלה.
- **התאמה `borderline`** ← קוראים את שתי המשרות ומחליטים: **אותה משרה?** רק אם התפקיד, הדרישות והמיקום תואמים ואין סתירה. בספק ← **לא כפילות** (עדיף משרה כפולה בלוח מאשר משרה שנבלעה). אם כפילות ← כמו `exact`, ומוסיפים התראה "אוחדה עם משרה דומה — בדוק" למשרה הקיימת.
- **בלי התאמה** ← המוח: בונים כרטיס לפי `brain.md` (עם `job-card.md` ו-`search.md`). שומרים כמסמך חדש ב-`jobs`, `doc_id` = ה-`id` מהתיבה, ושדה `agent_id` = אותו `id` (בלעדיו אי אפשר לזהות שהמשרה נסגרה) (עמוד שפוצל לכמה משרות: `<id>-1`, `<id>-2`...), עם: `first_seen: D`, `source`, `status` (`new` / `filtered`), `history: [{status, at: <עכשיו UTC>, note: "נמצא ע\"י <source>"}]`, `notes: ""`.
