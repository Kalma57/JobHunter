# פרומפט דרישות #3 — סוכני החברות (שכבה 1)

(טיוטה, 10/10/2026 — ממתינה לאישור המשתמש. שלב 8. המקורות והשכבות: [`sources.md`](../sources.md).)

## התפקיד
כל בוקר, לכל חברה בשכבה 1: למשוך את המשרות הפתוחות **בישראל** שעוברות את הפילטר של האתר, ולהעביר לסוכן הגדול **רק משרות שלא נראו בעבר**.
**קוד בלבד** — לא משתמש ב-Pro, לא קורא את המשרות "בהבנה", לא מחליט אם משרה מתאימה. זה תפקיד המוח.

## מבנה
- **סוכן אחד לכל מערכת גיוס**, לא לכל חברה: Greenhouse, Lever, Workday, Eightfold, Comeet.
- **החברות הן נתון, לא קוד.** רשימת החברות של כל מערכת (slug / tenant / כתובת) והפילטרים שלהן נמצאים בקובץ הגדרות אחד. הוספת חברה על מערכת קיימת = שורה בקובץ, בלי לשנות קוד.
- נקודת כניסה אחת: `python -m jobhunter.agents run --today D` — מריצה את כל הסוכנים ברצף (צעד 1 בריצת הבוקר, [`morning-run.md`](morning-run.md)).

## מה כל סוכן מחזיר (לכל משרה)
| שדה | חובה | הערה |
|---|---|---|
| `id` | ✅ | ייחודי ויציב: `<מערכת>:<חברה>:<מזהה המשרה באתר>` (למשל `lever:mobileye:60ebea6b-...`) |
| `source` | ✅ | שם המערכת והחברה, למשל `greenhouse:nebius` |
| `company` | ✅ | שם החברה כפי שהוא ב-`sources.md` |
| `title` | ✅ | כפי שהוא באתר, בלי שינוי |
| `url` | ✅ | הקישור לעמוד המשרה **באתר החברה** |
| `apply_url` | אם יש | קישור ישיר להגשה |
| `location` | ✅ | כפי שהוא באתר (טקסט); כמה מיקומים ← מופרדים בפסיק |
| `job_number` | אם יש | מספר המשרה של החברה (עוזר לכפילויות) |
| `posted_at` | אם יש | תאריך הפרסום מהאתר (המוח משתמש בו לכלל 60 הימים) |
| `description` | ✅ | **הטקסט המלא** של המשרה, ניקוי HTML לטקסט בלבד. בלי קיצור |

## הפילטר (מה נכנס)
1. **ישראל בלבד** — לפי שדה המיקום של האתר (או פילטר המיקום שלו, אם יש).
2. **מילות חיפוש** מתוך [`search.md`](../search.md): `Student`, `Intern`, `סטודנט` — בחיפוש של האתר אם יש, אחרת בקוד. **איפה מחפשים את המילה — ראה שאלה פתוחה 1.**
3. **בלי שום סינון נוסף בקוד** (תחום, אזור, ימים, ניסיון) — כל אלה של המוח. עדיף משרה מיותרת שהמוח יסנן מאשר משרה שהקוד בלע.
4. הפילטרים של כל אתר נכתבים בקובץ ההגדרות, **מוצגים למשתמש לאישור** לפני ההפעלה, ומשתנים רק כשמשנים את `search.md`.

## חובה
1. **משיכה מלאה** — לעבור על כל העמודים של התוצאות (pagination) עד הסוף. ספירה שלא תואמת לאתר = באג.
2. **רק משרות חדשות** — דרך `collect_new` מ-[`state.py`](../../jobhunter/state.py). משרה שכבר נראתה לא עוברת שוב, גם אחרי הפעלה מחדש של המחשב.
3. **כל משרה שעברה את הפילטר מסומנת "נראתה"** — גם אם לא חדשה — כדי שכלל 30 הימים ידע שהיא עדיין באתר.
4. **כשל של אתר אחד לא מפיל את הריצה.** האתר נכשל (שגיאה, timeout, מבנה השתנה) ← מדלגים עליו, **לא** מסמנים כלום כ"נראה", וכותבים שגיאה לדוח הריצה. הסוכן הגדול מציג את השגיאות בהתראה.
5. **אזהרת אפס:** אתר שבדרך כלל מחזיר משרות והיום החזיר 0 ← אזהרה בדוח (כנראה שבר, לא באמת אין משרות).
6. **נימוס כלפי האתרים:** בקשה אחת בכל פעם לכל אתר, השהיה קצרה בין עמודים, User-Agent מזוהה, ורק ממשקים ציבוריים שהאתר עצמו משתמש בהם.
7. **ספרייה סטנדרטית בלבד** (כמו שאר הקוד), אלא אם יוסכם אחרת.

## אסור
- לשלוח טפסים, להירשם, להתחבר או להגיש — קריאה בלבד.
- לעקוף חסימות (403, CAPTCHA). אתר שחוסם ← עובר לשכבה 3.
- לשנות, לקצר או "לשפר" את הטקסט של המשרה.
- להחליט על התאמה או כפילות — זה של המוח ושל הסוכן הגדול.

## רשת ביטחון — סריקה שבועית
פעם בשבוע (קוד בלבד): משיכה של **כל** המשרות בישראל בכל חברה, **בלי** מילות חיפוש. **מה עושים עם מה שנמצא — ראה שאלה פתוחה 2.**

## הבדיקה (שלב 8) — מוסכמת לפני הבנייה
**הסוכן הראשון:** Greenhouse + Lever — Nebius, ScaleOps, Cato Networks, Mobileye.
1. **ספירה:** מספר המשרות בישראל שהסוכן מחזיר = המספר באתר (בדיקה ידנית מול האתר, לכל חברה).
2. **פילטר:** המשתמש מקבל רשימה של כל המשרות בישראל, מסומנות "עבר / לא עבר" את הפילטר, ומסמן אם יש משרה רלוונטית שהפילטר פספס. **עובר אם:** 0 משרות רלוונטיות שפוספסו.
3. **רק חדשות:** הרצה פעמיים ברצף ← בפעם השנייה 0 משרות חדשות.
4. **כשל:** אתר מדומה שנכשל ← הריצה ממשיכה, השגיאה בדוח, ושום מזהה לא נמחק.
5. **בדיקות קוד** (pytest) על תשובות שמורות מהאתרים — בלי רשת.
