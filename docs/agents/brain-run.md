אתה רץ **בלי אדם**, בתיקיית הפרויקט. מותר לך רק **Read, Glob, Grep, Write**. אל תשאל שאלות.
הקוד כבר עשה הכל חוץ מהקריאה וההחלטה: משך את המשרות, סינן בקוד, הוריד כפילויות ודאיות, ויכתוב את הלוח בעצמו מהקובץ שלך.

## הצעדים
1. Read `state/plan/next.json`. `D` = `date`. אם `to_brain` = 0 ← כתוב `state/plan/<D>-cards.json` עם `{"cards": []}` וסיים.
2. Read את `files.brain` (`state/plan/<D>-brain.json`): רשימת משרות. לכל פריט: `doc_id`, `job` (כולל הטקסט המלא ב-`job.description`), `borderline` (מועמדים לכפילות, אולי ריק).
3. Read את [`brain.md`](brain.md), [`job-card.md`](../job-card.md) ו-[`search.md`](../search.md) — הכללים של הכרטיס ושל החיפוש. `search.md` כולל משוב של המשתמש — הוא קובע.
4. לכל פריט — **כרטיס אחד** לפי `brain.md`:
   - **יש `borderline`:** אותה משרה כמו המועמד? רק אם התפקיד, הדרישות והמיקום תואמים ואין סתירה. בספק ← **לא כפילות**. אם כפילות: `{"doc_id": "<של הפריט>", "duplicate_of": "<board_id של המועמד>", "duplicate_reason": "<שורה>"}` — בלי שדות כרטיס.
   - **אחרת:** אובייקט הכרטיס המלא של `brain.md` (כל השדות של "פורמט הפלט", כולל `relevance`, `status` = `new` / `filtered`, `rank` אם עברה, `far` אם רחוקה) **ועוד** `"doc_id": "<של הפריט>"`.
   - **כשלא בטוחים — עוברת:** `"status": "new"`, `"uncertain": true`, והתראה ב-`alerts` שמסבירה מה לא בטוח. לא מסננים בגלל תואר קרוב (מדעי המחשב, הנדסת מחשבים, חשמל ומחשבים), "שנה ב'" במדמ"ח (= שנה ג' בהנדסת תוכנה), תפקיד גבולי או אזור גבולי כמו ירושלים. מסננים רק כשהכישלון ברור (`search.md`, "כלל העל").
   - לא להמציא. מה שלא כתוב ← `not_stated`. כרטיס של HireMeTech שהטקסט שלו מוסתר ← התראה "המודעה קטועה".
5. Write `state/plan/<D>-cards.json`:
   ```json
   {"cards": [ {...}, {...} ]}
   ```
   **קובץ אחד, JSON תקין**, כרטיס לכל פריט ב-brain (פריט בלי כרטיס חוזר לתור למחר).
6. כתוב דוח קצר בעברית: כמה עברו / סוננו / כפילויות, ואילו משרות עברו.

## אסור
- לכתוב קובץ אחר מלבד `state/plan/<D>-cards.json`.
- לקרוא את כל הלוח — רק את `state/board/jobs/<id>.json` של מועמדי כפילות, אם צריך.
- לשנות סטטוס של משרה קיימת.
